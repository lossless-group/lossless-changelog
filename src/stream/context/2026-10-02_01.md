## Why Care?

Remaking a client's deck used to mean knowing the right things to say to a
coding agent: extract the slides, check the extraction, fan out designers who
must not copy the original, refactor into Astro sections, and make sure it plays.
That knowledge lived in one person's chat habits. Now it's a command anyone can
run, from whichever agent chat they already use.

## What's New?

- **`remake-deck` skill.** Say `/remake-deck "Acme" acme-decks path/to/deck.pdf`,
  or just "remake this deck", and the agent becomes the orchestrator. It
  extracts and audits the deck, has N designers (3 by default) each produce one
  coherent HTML + Tailwind deck in a clean room, refactors each into
  `Section__<Name>.astro` components, registers them, and verifies them in the
  Scroll-UI shell.
- **Works without subagents.** Agent chats that can't spawn subagents run the
  same plan with each role in sequence, with explicit rules to protect the
  designers' clean room, and say so up front.
- **The procedure isn't copied into the skill.** It points at
  `dididecks-ai/context-v/plans/Remake-Source-Deck-into-Design-Variants.md` and
  the prompts beside it, so improving the pipeline means editing one place.

## How to use it

Sync skills after pulling (`sync-skills-symlinks.sh` on macOS, `stow -R` on
Linux), then open an agent chat in or above a `dididecks-ai` checkout. Claude
Code users inside `dididecks-ai` also get the same thing as the committed
`.claude/commands/remake-deck.md` slash command, which needs no sync.
