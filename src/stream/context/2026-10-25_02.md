## Why Care?

Agents are good at git. Artifacts (open beta since 2026-10-01) makes git cheap enough to hand each one its own repo, instead of every agent cloning the same GitHub repo and fighting over branches. Cheap isn't free, though: it's billed per operation since 2026-10-14, a delete has no documented undo, and repo tokens are passwords that git will happily write into `.git/config`. This skill covers those parts.

## What's New?

- **`cloudflare-artifacts-interface/`**, marked draft.
- The model: namespaces, repos, remotes, forks, read-only baselines, and repo tokens.
- Three credentials that never substitute for each other: a Cloudflare API token for the control plane, a repo token for git, and a Worker binding with no token in code.
- Four safety tiers. Repo and namespace deletes, permanent jurisdiction namespaces, write tokens longer than a day, and bulk creation all need a yes.
- Token hygiene: always pass `scope` (minting defaults to `write`), use the header form so tokens stay out of `.git/config`, and revoke when done.
- Recurring jobs: a workspace per session, read-only handoffs, importing public and private repos, reading files without cloning, cleanup, and git notes for prompts and model output.
- `references/api-map.md`: every operation across REST, Wrangler, and the binding, tiered, plus limits.
- Uses the public skill / private config pattern. Accounts, env var names, and namespaces live in a gitignored `config/private.json`.

## What we learned testing it

- A token without the Artifacts permission gets a generic `Authentication error` (code 10000), not a permission error.
- `/user/tokens/verify` calls an account-owned token invalid; `/accounts/:id/tokens/verify` calls it active.
- Account-owned `cfat_` tokens do work for Artifacts, even though Artifacts isn't on Cloudflare's account-token compatibility list.

## What's next
