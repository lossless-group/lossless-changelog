## Why Care?

Before an agent can work well in a repo it needs to know what's in it. Graphify
builds that picture quickly: it parses the code instead of asking a model to read
it, so a graph of a project takes seconds, and every link it reports says whether
it was read from the source or inferred. We'd been using it for weeks through its
own installer, but it wasn't in this repo. So no other machine, harness, or
collaborator got it from us.

## What's New?

- **`graphify/` skill**, copied verbatim from what `graphify install` produces
  for version 0.9.32: `SKILL.md`, its `references/`, and upstream's MIT `LICENSE`.
- **`graphify/VENDORED.md`** records the source, the version, and the three
  commands to refresh it, and says not to edit the copy.
- **README** lists it beside Archify and the Chroma skills.

## Why a copy, not a submodule

Archify and Chroma's repos each contain a ready-made skill folder, so we pin them
as submodules. Graphify's repo doesn't: its skill ships inside the Python package
and is written out at install time. The installed output is the skill, so that's
what we vendor.

## Known Gotchas

- **The skill needs the CLI.** It runs `graphify`, and installs the `graphifyy`
  package on first use if it's missing. Keep both on the same version.
- **Machines that ran `graphify install` already have a real
  `~/.claude/skills/graphify` folder.** The sync script never replaces a real
  folder with a link, so that copy keeps loading. That's harmless at the same
  version. See `VENDORED.md` to switch.

## What's Next?

The context-v kit (`context-vigilance-kit`) will bundle graphify and use it as the
default for its `context.code_graph` role.
