## 🐛 Bug Fixes

### Claude Code Plugin Discovery

Fixed critical path resolution issues in `.claude-plugin/plugin.json` that prevented Claude Code from properly discovering Neo's agents and commands. All file paths are now correctly relative to the plugin root directory.

**Impact:** Users can now successfully install and use Neo as a Claude Code plugin without manual path adjustments.

#### Path Standardization

**Previous (Broken) Paths:**
```json
{
  "agents": ["./agents/neo.md"],
  "commands": [
    "./commands/neo.md",
    "./commands/neo-review.md",
    "./commands/neo-optimize.md",
    "./commands/neo-architect.md",
    "./commands/neo-debug.md",
    "./commands/neo-pattern.md"
  ]
}
```

**Fixed Paths:**
```json
{
  "agents": ["./.claude-plugin/agents/neo.md"],
  "commands": [
    "./.claude-plugin/commands/neo.md",
    "./.claude-plugin/commands/neo-review.md",
    "./.claude-plugin/commands/neo-optimize.md",
    "./.claude-plugin/commands/neo-architect.md",
    "./.claude-plugin/commands/neo-debug.md",
    "./.claude-plugin/commands/neo-pattern.md"
  ]
}
```

**Rationale:** Claude Code's plugin discovery mechanism expects paths relative to the repository root, not the `.claude-plugin` directory. This standardization ensures compatibility with Claude Code's file resolution logic.

**File:** `.claude-plugin/plugin.json:21-28`

#### Available Commands After Fix

All six Neo commands are now properly discoverable:

1. **`/neo:neo`** - Primary Neo agent for semantic reasoning and code suggestions
2. **`/neo:neo-review`** - Code review with semantic analysis
3. **`/neo:neo-optimize`** - Optimization suggestions
4. **`/neo:neo-architect`** - Architectural guidance
5. **`/neo:neo-debug`** - Debugging assistance
6. **`/neo:neo-pattern`** - Pattern extraction

## 📝 Technical Details

### Plugin Discovery Mechanism

Claude Code resolves plugin paths using the following logic:

1. Reads `plugin.json` from `.claude-plugin/` directory
2. Resolves all `agents` and `commands` paths **relative to repository root**
3. Validates file existence before registering

**Key Insight:** Even though `plugin.json` lives in `.claude-plugin/`, the paths within it must be relative to the repository root (where `.git` resides), not relative to the plugin manifest itself.

### Directory Structure

```
neo/                           # Repository root
├── .claude-plugin/
│   ├── plugin.json           # Manifest with paths
│   ├── agents/
│   │   └── neo.md            # Agent definition
│   └── commands/
│       ├── neo.md
│       ├── neo-review.md
│       ├── neo-optimize.md
│       ├── neo-architect.md
│       ├── neo-debug.md
│       └── neo-pattern.md
├── src/
│   └── neo/
│       └── __init__.py       # Version constant
└── pyproject.toml            # Project metadata
```

All paths in `plugin.json` must start from the repository root and include `.claude-plugin/` prefix.
