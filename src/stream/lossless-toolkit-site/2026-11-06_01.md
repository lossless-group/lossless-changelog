## Why Care?

The toolkit was two months stale. Its pages came from a copy of the vault
committed into this repo, and the only way to refresh that copy was a script
someone had to remember to run. Nobody had since September 8. About 480
tools and vertical entries were missing, and pages moved or deleted in the
vault were still live here.

Now the site reads the vault itself. A push to `lossless-content` reaches
toolkit.lossless.group in seconds.

## What's New?

- **Pages render from the vault's current head.** Tool, tag, and vertical
  pages render on request from whatever `lossless-content` holds on `master`.
- **A push purges the cache.** The site subscribes to
  [[lossless-hook-relay]], the org-wide webhook. When a push touches
  `tooling/` or `vertical-toolkits/`, the relay wakes `/api/content-hook`,
  which purges every cached page and warms the home page.
- **Moves and deletions are honored.** A page moved in the vault moves here.
  A page deleted there is a 404 here.
- **Umbrella folders keep their URLs.** The vault now nests
  `Venture-Capital-Firms/` under `Alternatives/`. Verticals group by the folder
  a file sits in, so `/verticals/venture-capital-firms/` stays put. Bioscience
  and its TechBio subfolder publish as two pages.
- **The copy in this repo is caught up**, to the vault as of today: 2,401 files.

## How it works

The vendored copy is still bundled, but as a starting point rather than the
source of truth. On each render, `src/lib/corpus.ts` checks the branch head
(a conditional request, at most every 10 seconds). When the head has moved,
it lists the two content folders in three API calls and compares each file's
git blob id with the copy it already holds. Only files that differ are
fetched. Against the September copy that was 757 files; against today's, one.

Nothing in that path throws into a page. If GitHub is unreachable, the last
good snapshot keeps serving, and a cold server falls back to the bundled copy.

Rendered pages sit on Vercel's CDN for five minutes under a single cache tag.
One tag, because almost every page counts or lists the whole corpus: a new
tool changes the home page, its tag pages, and the explorer's data together.
The five minutes only matter if a webhook delivery is lost, since GitHub
doesn't retry.

## Under the Hood

- **Output is `server` now**, with `@astrojs/vercel` and Astro's route cache.
  The five dynamic routes look up their entry at request time and return the
  404 page for one that isn't there.
- **`content-api.ts` stayed the single parser.** Its raw files now come from
  `corpus.ts` instead of `import.meta.glob`, and its memos rebuild when the
  corpus version changes. `client-tags.ts` follows the same rule.
- **The sitemap is an endpoint.** `@astrojs/sitemap` only lists prerendered
  routes, so it would have shrunk to nothing. The old filter rules came along:
  no `/client/`, no non-HTML routes.
- **Search is indexed from records, not HTML.** There's no built HTML for
  Pagefind to crawl now. `search-records.json` is prerendered at build, and
  `scripts/build-search-index.mjs` feeds it to Pagefind's node API with the
  same tag filters. Client portals are left out of search, since they're
  unlisted. One limitation: search reflects the last deploy, not the last
  push.
- **`sync-content.sh` mirrors deletions** and finds the vault relative to the
  site, instead of a hard-coded Linux path. The fixtures and `config.ts` are
  protected from `--delete`.
- **The acceptance tests request pages from a server** instead of grepping
  `dist/`. Run them against a baseline-pinned dev server:
  `CONTENT_SOURCE=baseline pnpm dev --port 4321`, then `pnpm build && pnpm test`.
  The `for_clients` check now crawls every sitemap URL, every client portal,
  and every static file a browser can fetch. All 20 pass, and so do the
  chip, tag-page, wikilink, and search browser drives.

## What's Next

- Set `GITHUB_TOKEN` and `RELAY_FORWARD_SECRET` on the Vercel project. Until
  they're set, the site serves the bundled copy and the hook refuses
  wake-ups.
- Rebuild the search index on push, so search catches up as fast as pages do.
