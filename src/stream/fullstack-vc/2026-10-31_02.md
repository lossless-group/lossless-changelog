## Why Care?

The context-vigilance kit has a baseline frontmatter template: `title`,
`date_created`, `date_modified`, `site_uuid`, `hex_code`, `authors`. Every
doc that carries all of them can be sorted, linked, and rolled up the same
way as every other doc in the tree.

This pass fills only what's missing, and only from facts. Nothing is
guessed, no existing value changes, and no date is set to the day of the
sweep.

## What's New?

- **`authors`** added to 18 docs that had none: the 16 docs of the
  2026-05-27 all-hands deck in `narratives/` (README included),
  `issues/Troubleshooting-SSG-Authentication-and-Port-to-SSR-w-Database.md`,
  and `sitemap/sections/Section__Areas-of-Venture.md`. Every commit to each
  of them is Michael's, so each reads `Michael Staton`.
- **`augmented_with`** written as a one-item list, not a bare string, in the
  10 docs that had it as a string: three issues, the projects page spec, both
  specs, and all four tasks. The model strings are exactly as they were.

Every doc already had its `title`, `date_created`, `date_modified`,
`site_uuid`, and `hex_code`, so those are unchanged. Status and tag values
were already Title-Case.

Part of the tree-wide sweep planned in the context-vigilance kit:
`ai-labs/context-vigilance-kit/context-v/plans/Retrofit-Every-Repo-to-OKF-Then-the-Kit-Frontmatter.md`.
