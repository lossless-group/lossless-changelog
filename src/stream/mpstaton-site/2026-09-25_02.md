## Why Care?

Two things shipped. One is a new page. The other is the kind of bug that only
shows itself when you are watching.

## What's New?

**`/psp` renders a Personal Strategic Plan** from one markdown file, with a
sticky heading rail and a generated share card. It is linked from the nav.

**`/api/og` no longer depends on Google Fonts at request time.** Inter Bold now
ships with the deploy.

## How it Works

The plan is authored as a single markdown document and imported with `?raw` into
a prerendered page, so the file is inlined at build time. There is no runtime
filesystem read and nothing extra to get into the serverless bundle, which after
this morning's Open Graph cache incident felt like the right default.

The source is a Google Docs form, so nearly every block in it is a table — 41 of
them on the rendered page. They do three unrelated jobs:

| Shape | Job |
|---|---|
| 1 column | a labelled prose box: "the prices I am willing to pay…" |
| 2 columns, 1 row | the goal's header band |
| 3+ columns | an actual data table: weekly plans, the scorecard |

The markdown gives them nothing to tell them apart, so `src/styles/psp.css` uses
`:has()` to do it structurally. A one-column table renders as a card with its
label above the copy; a four-column one renders as a real table with a shaded
header row and a narrow week column.

Two details the page gets right by reading from the pipeline rather than
recomputing:

- **Headings come from `tree.data.headings`.** The first pass re-slugified the
  heading text by hand, which produced a table of contents whose links all
  looked fine and none of which landed, because they did not match the anchors
  `AstroMarkdown` actually emits.
- **The author identity table is stripped at render time only.** Name, phone,
  age, city and handles are metadata about the author rather than part of the
  plan, and the page is public. The markdown keeps them, because the shared
  document this is exported to expects them.

## Under the Hood

The Open Graph fix is the more interesting half. `loadFont()` fetched the Google
Fonts CSS API, parsed a `fonts.gstatic.com` URL out of the response, and fetched
that, all inside the request, caching only in the module scope of a single warm
process. Every cold start paid for it again, and there was no fallback: the
`catch` turned any failure into `Failed to generate image: fetch failed`.

That is the same shape as the cache bug fixed earlier today — a build-time
assumption running in a request path — and it had been sitting in the endpoint
the whole time, hidden by the fact that the fetch usually succeeds.

Inter Bold is now a 326 KB file in `src/assets/fonts/`, added to the adapter's
`includeFiles` so it travels with the function, read with `readFileSync` and
cached the same way. The network path survives only as a last resort, behind an
`existsSync` check and a warning.

Verified by rendering a card against the built function with `fetch` stubbed to
throw on `fonts.googleapis.com` and `fonts.gstatic.com`: 200, a valid 55 KB PNG,
and the font CDN never touched. The first version of that test blocked `fetch`
entirely and failed, which was the test's fault rather than the endpoint's —
`resvg` loads its WebAssembly through a `data:` URL.
