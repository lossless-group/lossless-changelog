## Why Care?

Long-form client documents kept getting built as bespoke pages. The last one
put the *brief* in markdown and the actual copy inside hand-written components,
one file per slide, so changing a sentence meant editing a component and the
design drifted a little further from the argument every time.

This is the correction. A proposal is now a folder of markdown files. Each one
picks a layout from a small fixed vocabulary in its frontmatter, and the design
lives in one stylesheet. Editing a sentence never means opening a component.

## What's New?

- **`/proposals/[slug]`** — a gated, noindex document surface, separate from
  the investment-promotion path it used to share. One address: locked shows the
  unlock form, unlocked shows the document.
- **Six layout primitives** — `cover`, `prose`, `two-column`, `stat-row`,
  `table`, `band` — plus a `tone` key that drains one column and lights
  another, for before/after comparisons.
- **Charts from markdown.** A ```vega-lite fence renders to inline SVG.
- **A print view and a PDF export** — same loader, same markdown, light palette.
- **`pnpm audit-citations`** — enforces the hex-code citation conventions.
- **Per-partner brand marks**, rendered as CSS masks so one asset works on the
  dark screen document and the light print page.

## How it Works

Sections are parsed one file at a time, which means each file's footnotes
number from 1. The loader walks every tree in document order and rewrites the
citation index against a document-wide map, so a source cited in section two
and section nine gets one number and one entry.

The same discipline runs through the table of contents: chapter titles become
depth-2 entries, each section's own headings nest beneath at depth 3, and a body
heading whose slug collides with one already in the outline is dropped rather
than shipped as an anchor that jumps to the wrong chapter.

## Under the Hood

**The charts took three attempts and the first two failures looked like
successes.** Loading Vega from a CDN pulled a mismatched pair — Vega-Lite 6
compiling against a Vega 5 runtime — and the compile threw, leaving an *empty*
`<svg>` behind. Every check for "did an svg appear" passed. Twice.

They now compile server-side to inline SVG. No network at view time, no version
skew, and the failure mode is visible instead of invisible. Text is emitted as
`currentColor` so one render reads correctly on both the dark document and the
light print stylesheet.

Two smaller fixes fell out of the same work:

- `AstroMarkdown` emitted `<td>` for every cell including inside `<thead>`,
  which silently disabled every `th` rule in the site's stylesheets. Header
  cells are now `<th scope="col">`.
- OpenGraph titles arrive HTML-escaped and were being escaped again, so an
  ampersand rendered as a literal `&amp;`. Decoding now converges, and applies
  to image URLs too — a CDN share image with query parameters was having its
  `&` corrupted.

## What's Next

The PDF is still a one-off export. The content already comes from the live
route, so nothing can drift — only the trigger is manual. Wiring it into the
build is the remaining step.
