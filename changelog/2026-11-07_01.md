## Why Care?

The aggregate was only as fresh as the last time someone ran `pnpm sync` and
redeployed. That had last happened five weeks ago: 38 of the 47 streams had
moved on since, and entries shipped this week were nowhere on the site.

Now the site reads each project's `changelog/` itself. A push to any of those
repos reaches changelog.lossless.group in about a minute.

## What's New?

- **Entries render from each repo's current branch.** Stream and entry pages
  render on request from whatever the source repo holds on the branch its
  stream declares.
- **A push purges the cache.** The site subscribes to [[lossless-hook-relay]]
  for every repo and branch its streams read, 44 in all. When a push touches a
  stream's changelog directory, the hook refreshes just those streams and
  purges the cached pages.
- **Deletions and moves are honored.** An entry removed upstream is a 404
  here, and one moved into a project shows up under it.
- **The committed copy is caught up**: 699 entries across 47 streams.

## How it works

The committed copy under `src/stream/` is still bundled, now as a starting
point rather than the source of truth. On each render, `src/lib/corpus.ts`
re-lists any stream it hasn't checked in the last minute. Each listing is a
conditional request, so a stream that hasn't moved costs a 304, which GitHub
doesn't count against the rate limit. When a listing has changed, each file's
blob sha is compared with the one already held, and only the files that
differ are fetched.

A fetched entry gets exactly what `pnpm sync` gives it: the same path
denylist, the same roll-up guard, the same provenance stamp. A live entry and
a synced one are byte-identical.

The hook can only reset the instance that receives it. Another instance may
still hold a minute-old listing and re-cache it. So the hook purges twice:
once at once, and again after every instance's minute has run out.

## Under the Hood

- **Output is `server` now**, with `@astrojs/vercel` and Astro's route cache.
  Pages sit on Vercel's CDN for five minutes under one `content` tag. The share
  stubs under `/s/` stay prerendered; they read no stream data.
- **`streams.ts` builds its model from the corpus** and rebuilds it when the
  corpus version moves. Every export keeps its signature, and `totals` became
  getters, so no page or component changed how it reads.
- **Live sync needs `GITHUB_TOKEN`.** Forty-seven listings would spend an
  anonymous client's 60 requests an hour in one pass, so without a token the
  site serves the committed copy.
- **Not live yet:** the commit, line, daily, and icon data (`_commits.json`,
  `_lines.json`, `_daily.json`, `_icons.json`) still come from their sync
  scripts and refresh on deploy.

## What's Next

- Set `GITHUB_TOKEN` and `RELAY_FORWARD_SECRET` on the Vercel project. Until
  they're set, the site serves the committed copy and the hook refuses
  wake-ups.
