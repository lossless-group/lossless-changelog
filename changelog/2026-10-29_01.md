# Specs Speak the Kit's Metadata Dialect, and Bylines Get a Plan

## Why Care?

Yesterday this repo's `context-v/` became an Open Knowledge Format bundle. Today its two specs finish the job: they now use the same frontmatter vocabulary as the rest of the Lossless tree, so anything that reads the standard keys reads these too. And a new plan takes on a problem every changelog aggregator hits sooner or later: one person, written several ways.

## What's New?

- **Standard keys and values.** Both specs had `version: 0.1.0.0` and `status: draft`. They now read `at_semantic_version: 0.1.0.0` and `status: Draft`. Same values, standard spelling. Nothing else in either doc changed, and no dates were touched: this is a compliance change, not a content change.
- **A plan for author aliases.** [[Maintain-an-Authors-List-Enables-Naming-Aliases]] adds an `aliases` list to each person in this site's authors registry, so `Michael Staton`, `Michael P. Staton`, and `mpstaton` all resolve to one byline with one headshot. Source frontmatter keeps whatever its author wrote; the registry absorbs the variation. A build report will list every author string that resolves to nobody, as the worklist for new aliases.

## Under the Hood

- Every edit was made by hand, one doc at a time. No script touched any frontmatter.
- `context-v/plans/` is new, with its own `index.md`, and the root `index.md` now lists it.
- The resolver the plan extends is `src/lib/people.ts`, which already matches on first+last name tokens. The plan keeps that as a fallback and makes it refuse ambiguous matches.
